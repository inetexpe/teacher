# Синхронізація кабінету викладача (Supabase)

Усередині Telegram апка (`index.html`) зберігає дані в Supabase через серверну
функцію `api`. Поза Telegram вона працює локально, у пам'яті браузера.

## Налаштування (один раз)

1. **Таблиці.** Supabase → SQL Editor → New query → вставте вміст `schema.sql` → Run.
2. **Функція.** Edge Functions → Deploy a new function → Via Editor.
   Назва функції — `api`. Замініть код вмістом `functions/api/index.ts` → Deploy.
3. **Вимкніть перевірку JWT.** У функції `api` → Details → вимкніть
   «Verify JWT with legacy secret» (або «Enforce JWT verification») → Save.
   Функція сама перевіряє вхід через підпис Telegram.
4. **Секрет BOT_TOKEN.** Edge Functions → Secrets → Add new secret:
   `BOT_TOKEN` = токен бота з @BotFather.
5. **Секрет TEACHER_IDS.** Відкрийте бота в Telegram → налаштування апки → там указано
   ваш Telegram ID. Додайте секрет `TEACHER_IDS` = цей ID (кілька — через кому).
   Без нього викладачем може стати будь-хто, хто відкрив бота без запрошення.

## Як це працює

- Викладач: усі дані — один документ у таблиці `workspaces` з номером версії.
  Якщо два пристрої зберігають одночасно, другий отримує свіжу версію.
- Учень відкриває `t.me/<бот>?startapp=s_<код>`; код береться з профілю учня
  (кнопка «Запросити»). Telegram-акаунт учня прив'язується в таблиці `links`.
- Учень бачить лише свій профіль без нотаток викладача, свої уроки й матеріали.
  Його відмітки ДЗ і запити на перенесення пишуться в `student_actions`; апка
  викладача забирає їх (при відкритті й кожні 30 с) і переносить у свої дані.
- З браузера до таблиць доступу немає: RLS увімкнено без правил, пише лише функція.
